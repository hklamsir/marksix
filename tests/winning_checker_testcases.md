## 四、驗證方法與結論

- 每個「正常」案例同時以系統優化公式路徑（`runCheck`，與 `js/app.js` 的 `doCheck` / `renderMultiCheckResult` 邏輯一致）與獨立暴力列舉（`bruteForce`，僅依 `resolveCheckerPrizeTier` 逐注分類）計算，二者每獎級注數與總獎金必須完全一致，以此確證超幾何分佈公式與「特別號碼拆分」邏輯正確。
- 錯誤 / 異常案例斷言系統按設計回傳錯誤或記錄其實際（未防護）行為。
- 本次執行結果：**37/37 通過，0 失敗**。

## 五、發現的系統行為 / 建議

1. **缺少號碼去重**（E-02）：重複號碼被視為不同號，會讓中獎注數異常偏高，建議投注前對號碼池 `Set` 去重。
2. **膽腳重疊未偵測**（E-03）：膽與腳含相同號會產生重複號組合，建議組合前檢查交集為空。
3. **號碼範圍未校驗**（E-04 / A-01）：接受 >49 或非數值，建議投注前驗證 `1≤n≤49` 且為整數。
4. **二/三獎金缺漏會靜默捨棄**（A-05）：`checkerPrizeAmount` 對二/三獎無保底，資料缺漏時中獎注數被「吃掉」而不報錯，建議補保底值或顯式警示。
5. **膽碼上限僅在 UI 攔截**（A-03）：`doCheck` 未拒絕 >5 膽的資料旁路輸入，建議在 `doCheck` 內也加 `bankerNumbers.length <= CHECKER_MAX_BANKERS` 防護。
